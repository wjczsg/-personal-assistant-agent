# 学习与求职中的个人资料助理

一个面向学生与求职者的 AI 应用开发实践项目。用户可以上传自己的学习笔记、项目资料等文本，在聊天中基于资料提问，也可以让助理提出学习或求职待办建议；新增待办须经用户在后续消息中明确确认。项目目前以单用户本地演示为主，还不是可供多人注册使用的线上产品。

项目的重点不是把所有事情交给模型自动执行，而是把**个人资料检索、工具调用和用户确认**串成一条可检查的工作流。计算器、时间和天气等通用工具仍保留，但不再作为项目的主要定位。

## 目标场景与当前范围

- **围绕资料提问**：上传学习笔记、项目说明或求职准备资料后，提问相关内容；Agent 可按需检索文档片段，并依据片段组织回答。
- **把建议变成行动**：根据对话或文档内容提出一条待办提案，展示内容后等待用户回复“确认”或“取消”；只有确认后才写入待办。
- **记住较稳定的背景**：在模型调用记忆工具时保存长期目标、偏好或个人背景；后续对话可检索有效记忆。

目前文档只支持 UTF-8 `.txt` / `.md`，可用文本文件模拟笔记或求职资料；PDF、Word、简历解析、岗位匹配、自动制定完整学习计划和用户注册登录**尚未实现**。

## 已实现的功能

- **网页对话**：FastAPI 提供聊天接口和简洁的 Web 页面。
- **文档问答（基础 RAG）**：网页可上传不超过 1 MB 的 UTF-8 `.txt` / `.md` 文档，原文保存在 SQLite；上传后自动分块并写入 Chroma 的 `document_chunks` 集合，与长期记忆分开。模型需要文档依据时，可调用检索工具获取当前用户的片段，再根据原文回答。
- **Function Calling**：模型按需选择计算器、当前时间、天气、待办操作、保存长期记忆和检索上传文档等工具。
- **聊天确认添加待办**：模型调用 `propose_todo` 时只保存一条待确认提案，不立即添加待办。下一条消息回复“确认”或“取消”才处理；有多条待确认提案时需回复“确认提案 #编号”等明确指令。原来的直接添加函数仍在代码中，但不再作为模型工具开放。
- **待办查询**：可以查询未完成、已完成或全部待办；默认只显示未完成，完成的待办不会丢失。
- **删除待办**：明确指定待办编号后可永久删除；按内容删除时先查全部待办，不能唯一确定时不删除。
- **修改待办**：按编号修改文字，保持原有完成状态；目标不明确时先查列表或询问用户。
- **连续工具调用**：一次任务可以先查天气，再根据结果决定是否提出待办建议；用户在下一条消息确认后才真正添加。每次请求最多进行三轮模型工具调用。
- **天气查询**：支持当前天气，以及城市当地今天起未来 16 天内的每日预报；可以使用“明天”“后天”或 `YYYY-MM-DD` 日期。
- **两种记忆**：SQLite 保存最近对话、待办和长期记忆原文；Chroma 为长期记忆建立向量索引。长期记忆在 SQLite 中有 `active`（有效）和 `superseded`（已被取代）状态，检索结果进入 Agent 前会过滤掉失效记忆。
- **便于学习**：核心模块有中文注释，并包含天气、连续工具调用、记忆状态与检索等自动化测试。

## 工作流程

```text
浏览器 → FastAPI /api/chat → Agent
                            ├─ 从 SQLite 读取最近对话
                            ├─ 从 Chroma 检索长期记忆 → 用 SQLite 状态过滤
                            └─ 请求大模型
                                ├─ 直接回答
                                └─ 按需调用工具注册表中的工具
                                    ├─ 检索当前用户的 document_chunks → 依据片段回答
                                    └─ 计算器、天气、待办等 → 根据结果回答

新增待办：模型调用 propose_todo → SQLite 保存 pending 提案 → Agent 展示提案
          → 用户下一条消息明确确认/取消 → 确认时写入 todos，取消时不写入
```

待办确认由后端根据用户后续发送的明确回复处理，不是模型在同一轮对自己的提案作出批准。重复确认不会重复添加待办；若同时存在多条待确认提案，需要指定提案编号。该流程**只覆盖新增待办**，不覆盖修改、完成或删除待办。

当前上下文只有按**数量**限制：每次读取最近 10 条对话、最多 3 条相关长期记忆，文档工具最多返回 3 个片段，模型最多进行 3 轮工具调用。这不是完整的上下文管理：一条很长的消息或工具结果仍可能让请求过长；超过 10 条的旧对话会直接不再送给模型，也没有先提炼摘要。长期记忆检索不能代替对话摘要。

长期记忆并不是把所有聊天内容都写进向量库。只有模型判断用户明确表达了长期目标、稳定偏好或个人背景，并调用 `save_memory` 时，才会同时写入 SQLite 和 Chroma。后续提问时，Agent 自动检索相关记忆作为回答参考。上传的文档片段使用另一集合，不会变成长期记忆。

记忆状态以 SQLite 为准：每次长期记忆检索先取得当前用户的有效记忆编号，再让 Chroma 按语义排序；返回的片段若不在有效编号中，就不会送入 Agent。若靠前的结果都已失效，检索会逐步扩大候选范围，避免漏掉排在后面的有效记忆。旧版数据库会在服务启动时补上 `status` 和 `superseded_by` 字段，已有记忆默认保持有效。当前只具备数据库层按编号标记“被取代”的能力，**尚未提供网页操作或 Agent 工具来自动标记旧记忆**；仅说“旧目标作废”还不能保证数据库状态被修改。

文档检索由模型通过 `search_uploaded_documents` 工具按需选择：普通聊天不再预先查询文档；模型调用工具后，Python 才从 `document_chunks` 中检索当前用户最多 3 个片段，并把原文与文件名、文档编号、片段编号交回模型。工具参数只有检索问题，用户编号由 Agent 提供，模型不能指定其他用户。工具返回空结果或检索故障时，模型应说明缺少依据，而不是猜测文档内容。模型是否正确选择工具仍需测试，不能保证每次都选对。

模型请求和多轮工具调度目前主要由项目自身实现；计算器工具已作为小范围示例使用 LangChain 的 `langchain-core` 包装。项目**不是**整体基于 LangChain 构建的。

## 近期进展（2026-10-12）

- 为长期记忆增加有效／已被取代状态和取代关系；迁移旧数据库时不擅自判定已有记忆失效。
- 长期记忆检索接入状态过滤，并补充“前几条均失效时继续寻找有效记忆”等测试。
- 新增待办提案表与创建／确认／取消接口；Agent 添加待办时先提出建议，并由用户下一条聊天消息确认或取消。

## 后续方向（未实现）

- **上下文管理（优先）**：统计实际发送给模型的 token，为历史对话、记忆和工具结果分别设预算；超出时优先保留当前问题与必要证据，并将较早对话压缩为可核对的摘要，而不是只按条数截断。需要测试长对话下是否丢失用户目标、是否超出模型限制，以及压缩后是否改变事实。
- **提案纠错**：允许用户在确认前修改待办提案，并再次核对修改后的完整内容；当前只能确认或取消。
- **资料处理**：支持 PDF、Word 等真实资料格式，并完善文档管理、解析失败处理与来源核验。
- **质量验证**：建立贴近学习和求职场景的固定问题集，检查文档检索、工具选择、提案内容及确认流程，而不只依赖少量手动体验。
- **面向真实用户**：补登录认证、用户数据隔离、隐私保护和部署能力；目前页面使用固定用户标识，不能直接作为多用户服务上线。
- **记忆纠错**：让用户查看、修正或删除长期记忆，并把旧记忆失效操作接入交互；目前仅有数据库层的状态管理。

## 本地运行

需要 Python 3.12。以下命令在 Windows PowerShell 中运行，先进入本项目根目录：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

编辑 `.env`，填写兼容 OpenAI Chat Completions 接口的模型配置：

```dotenv
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=你的密钥
LLM_MODEL=你的模型名称
```

启动服务：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

打开 <http://127.0.0.1:8000/> 使用网页；接口文档位于 <http://127.0.0.1:8000/docs>。停止服务按 `Ctrl+C`。

分块函数优先选择段落或句末边界，默认每块最多 500 个字符、相邻块重叠约 50 个字符。上传时先把原文保存到 SQLite，再自动分块并写入 Chroma；接口等索引完成后才返回。页面会显示文档编号、是否索引成功，以及成功时的块数。第一次计算嵌入向量可能需要较长时间，请等待页面状态更新。

若页面显示“已保存但自动索引失败”，原文仍在 SQLite。可在 <http://127.0.0.1:8000/docs> 找到 `POST /api/documents/{document_id}/index`，填入页面显示的文档编号，并提交 `{"user_id":"web-user"}` 重试。重复索引会更新相同片段，不会无限新增。以前上传但尚未索引的文档不会因这次代码更新而自动补建索引，也可以用该接口补建。

建好索引后，回到网页聊天框，提出一个能从文档中找到答案的问题。Agent 会把检索片段连同问题交给模型，提示模型根据片段回答并说明出处；它仍使用原来的 `/api/chat` 接口，不需要切换页面或选择专门模式。实际回答是否正确，仍需对照原文检查。

需要单独检查检索结果时，可在 <http://127.0.0.1:8000/docs> 调用 `POST /api/documents/search` 并提交 `{"user_id":"web-user","query":"文档里提到了什么？"}`。接口返回最多 3 个相关片段及文件名、文档编号和块序号；它只搜索该用户的**已索引**文档，不调用大模型生成答案。网页上的临时检索测试区已移除。Chroma 总会返回相对最接近的片段，所以命中不一定真正相关，需要核对原文。

> 如果不填写 `LLM_API_KEY`，项目会进入演示模式：可以启动网页、上传文档并保存对话，但聊天时不会调用大模型、自动选择工具，也不会执行 Agent 的长期记忆或文档检索与问答。完整功能需要配置可用的模型及密钥。

## 可以试试

在网页中依次提问：

1. `12 * 8 等于多少？`
2. `北京明天的天气怎么样？`
3. `帮我添加一个待办：周末整理简历。`（先显示提案；下一条消息回复 `确认` 才会真正添加，也可回复 `取消`）
4. `我还有哪些待办？`
5. `把刚才整理简历的待办标记为完成。`
6. `我已经完成了哪些待办？`
7. `列出我的全部待办。`
8. `删除待办 #1。`（请换成列表中实际存在的编号；删除后无法恢复）
9. `把待办 #2 改成：周日完善简历。`（请换成列表中实际存在的编号）
10. `请记住：我毕业后想从事 AI 应用开发。`
11. `我毕业后想做什么方向的工作？`

第 10、11 句用于观察长期记忆的保存与检索。模型负责决定是否调用工具，因此实际调用情况取决于所配置模型的 Function Calling 能力。

测试文档问答时，上传一份内容独特的新文档，确认页面显示“已保存并建立索引”，然后直接问一个文档里有明确答案的问题：前端应显示“已使用：search_uploaded_documents”，回答应能对应到文档原文。再问天气、待办等无关问题，观察它是否没有调用文档检索；也试一个文档里没有答案的问题，检查模型是否承认缺少依据。

测试“资料 → 行动”时，可在文档中写一项明确的学习任务，再问“根据我上传的资料，帮我把这项任务加入待办”。检查 Agent 是否先检索资料并展示待确认提案；此时查询待办不应看到新记录。回复 `确认` 后再查待办，确认只新增一条。模型是否选中检索或提案工具仍受模型能力影响，不能仅凭一条成功案例认定流程始终可靠。

## 项目结构

```text
app/
├── main.py           # FastAPI 入口、网页和聊天接口
├── agent.py          # 对话组织、长期记忆检索和模型工具调用循环
├── tool_registry.py  # 给模型看的工具定义及工具执行映射
├── tools.py          # 计算器、时间、天气、待办和记忆工具的具体逻辑
├── database.py       # SQLite：对话、待办、长期记忆和上传文档原文
├── document_chunking.py # 文档原文的分块规则
├── document_indexing.py # 读取原文、分块并触发文档索引
├── vector_store.py   # Chroma：长期记忆检索、文档片段索引与检索
├── config.py         # .env 配置读取
├── schemas.py        # 接口请求与响应的数据格式
└── static/           # 网页的 HTML、CSS 和 JavaScript
tests/                # 自动化测试
```

运行测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

本地运行会产生 `assistant.db` 和 `chroma_data/`；`.env`、数据库和向量索引数据已被 `.gitignore` 排除，不会随代码提交。

## 当前边界

这是学习项目，不是已经具备生产环境安全措施的多用户服务。网页默认使用 `web-user` 作为用户标识，尚无登录认证；目前只有“新增待办”走聊天确认，完成／删除／修改待办和保存长期记忆仍沿用原有工具流程。“确认”与“取消”需明确回复，多条待确认提案需带编号，暂不支持在确认前直接编辑提案文字。天气工具不支持历史天气或指定小时；长期记忆尚未提供去重、面向用户的查看／纠错／删除操作及检索相关性阈值。SQLite 中标为失效的记忆不会进入 Agent 上下文，但旧向量仍留在 Chroma，暂未自动清理。上传请求会等待向量索引完成，大文档可能较慢；失败时原文保留，但当前没有后台重试任务。文档工具是否被调用由模型决定，可能漏调或误调；文档检索也没有相关性阈值，可能漏掉正确片段或返回无关片段。模型给出的来源尚未由程序逐条核验。Chroma 当前使用默认 Embedding 模型，中文语义检索效果仍有优化空间。
